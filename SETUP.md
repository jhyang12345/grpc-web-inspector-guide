# Set up gRPC-Web Inspector in your web application

The browser extension can inspect RPCs only after the web application connects
its client or transport to the API injected into the page. Use the setup that
matches the RPC library already installed in your application.

The integration is optional at runtime. When the extension is not installed,
the page APIs are absent and RPCs continue through the normal client or
transport. You do not need to add an Inspector npm dependency.

The examples use TypeScript. For JavaScript, remove type-only imports and type
annotations.

This file is also suitable for publishing as a GitHub Gist. It contains the
complete setup snippets, while its example-file links point back to the public
guide repository.

## Before you start

1. Install gRPC-Web Inspector from the
   [Chrome Web Store](https://chrome.google.com/webstore/detail/grpc-web-developer-tools/kanmilmfkjnoladbbamlclhccicldjaj).
2. Identify the client library that creates browser RPCs:
   - a client generated by `protoc-gen-grpc-web`;
   - Connect-ES using `@connectrpc/connect-web` or legacy
     `@bufbuild/connect-web`; or
   - protobuf-ts using `@protobuf-ts/grpcweb-transport`.
3. Find the active client or transport factory. Reuse its endpoint, options,
   credentials, and existing interceptors.
4. Add the matching setup before the first RPC that should be captured.
5. In an SSR or hybrid application, keep browser globals behind a client-only
   boundary or a `typeof window !== "undefined"` guard.

## Generated grpc-web clients

Use this pattern for clients generated by `protoc-gen-grpc-web` 1.0.4 or newer.
Register every long-lived client instance. The immediate call handles an API
that is already present, and the readiness event handles later extension
injection.

```ts
import { EchoServiceClient } from "./generated/EchoServiceClientPb";

export const echoClient = new EchoServiceClient("https://api.example.com");
const grpcWebClients = [echoClient];

function installGrpcWebDevtools(): void {
  if (typeof window === "undefined") return;
  window.__GRPCWEB_DEVTOOLS__?.(grpcWebClients);
}

if (typeof window !== "undefined") {
  installGrpcWebDevtools();
  window.addEventListener("grpc-web-dev-tools-ready", installGrpcWebDevtools);
}
```

Repeated registration is safe. Keep the installer in a stable client setup
module rather than a component render path. Register all existing client
instances in the same array, including clients for different services.

Do not capture the global once with a permanent no-op fallback:

```ts
// Wrong: this stays a no-op if the extension injects its API later.
const enableDevTools = window.__GRPCWEB_DEVTOOLS__ || (() => {});
```

### Replay adapters for generated clients

The Inspector can reconstruct supported scalar, enum, bytes, repeated, and
inferable nested fields through generated setters. If a method contains custom
or nested fields that cannot be inferred safely, register a method-specific
adapter inside the same readiness-safe installer:

```ts
function installGrpcWebDevtools(): void {
  if (typeof window === "undefined") return;
  const devtools = window.__GRPCWEB_DEVTOOLS__;
  if (!devtools) return;

  devtools([echoClient]);
  devtools.registerMethod("/example.EchoService/Send", {
    createRequest(json) {
      const request = new SendRequest();
      request.setMessage(String(json.message ?? ""));
      request.setLabelsList(
        Array.isArray(json.labels) ? json.labels.map(String) : []
      );
      return request;
    },
  });
}
```

Use the exact method path displayed by the Inspector. Prefer generated message
constructors and setters; do not pass an untyped plain object to the transport.

[examples/generated-grpc-web.ts](https://github.com/jhyang12345/grpc-web-inspector-guide/blob/main/examples/generated-grpc-web.ts)

## Connect-ES

Use a late-bound interceptor with `createGrpcWebTransport()` or
`createConnectTransport()`. Looking up the injected API for every request makes
the transport independent of extension injection timing.

```ts
import type { Interceptor } from "@connectrpc/connect";
import { createGrpcWebTransport } from "@connectrpc/connect-web";

const grpcWebDevtoolsInterceptor: Interceptor = (next) => (request) => {
  const devtools = typeof window === "undefined"
    ? undefined
    : window.__CONNECT_WEB_DEVTOOLS__;
  return devtools ? devtools(next)(request) : next(request);
};

const transport = createGrpcWebTransport({
  baseUrl: "https://api.example.com",
  interceptors: [
    grpcWebDevtoolsInterceptor,
    ...applicationInterceptors,
  ],
});
```

For the Connect protocol, use the same interceptor with
`createConnectTransport()`. For a legacy application, keep the packages already
installed and import the equivalent types and factories from
`@bufbuild/connect` and `@bufbuild/connect-web`; integrating the Inspector does
not require a package migration.

Put the Inspector wrapper before authentication, retry, tracing, and other
application interceptors without changing their relative order. An edited
replay can then pass through the rest of the application pipeline and obtain
fresh credentials where applicable.

Do not create an interceptor array conditionally and push into it after the
transport has been created. A transport may snapshot or compose its interceptor
list during construction.

## protobuf-ts

Use a late-bound `RpcInterceptor` with `GrpcWebFetchTransport`. Pass the exact
transport base URL to the Inspector so captured backend URLs are correct.

```ts
import { GrpcWebFetchTransport } from "@protobuf-ts/grpcweb-transport";
import type { RpcInterceptor } from "@protobuf-ts/runtime-rpc";

const baseUrl = "https://api.example.com";

const grpcWebDevtoolsInterceptor: RpcInterceptor = {
  interceptUnary(next, method, input, options) {
    const devtools = typeof window === "undefined"
      ? undefined
      : window.__GRPCWEB_DEVTOOLS_PROTOBUF_TS__;
    return devtools
      ? devtools.interceptUnary({ baseUrl, next, method, input, options })
      : next(method, input, options);
  },

  interceptServerStreaming(next, method, input, options) {
    const devtools = typeof window === "undefined"
      ? undefined
      : window.__GRPCWEB_DEVTOOLS_PROTOBUF_TS__;
    return devtools
      ? devtools.interceptServerStreaming({
          baseUrl,
          next,
          method,
          input,
          options,
        })
      : next(method, input, options);
  },
};

const transport = new GrpcWebFetchTransport({
  baseUrl,
  interceptors: [
    grpcWebDevtoolsInterceptor,
    ...applicationInterceptors,
  ],
});
```

The per-call lookup removes the need for a readiness listener. The extension
also emits `grpc-web-dev-tools-protobuf-ts-ready` if the application has another
reason to observe installation.

Keep the Inspector wrapper before existing application interceptors, retain the
transport's current fetch configuration, and confirm the signatures exported
by the installed protobuf-ts version. Do not upgrade the runtime or regenerate
messages only to match this example.

## Verify the integration

1. Build and reload the web application.
2. Open browser DevTools and select the **gRPC-Web** panel.
3. Issue a new unary or server-streaming RPC. Requests made before registration
   are not captured retroactively.
4. Confirm that the entry contains request data, response or stream messages,
   status or error, frame URL, backend URL, timestamps, duration, and stream
   time-to-first-message.
5. In the inspected page's console, use this read-only capability check if the
   expected API is missing:

   ```js
   ({
     grpcWeb: typeof window.__GRPCWEB_DEVTOOLS__,
     connect: typeof window.__CONNECT_WEB_DEVTOOLS__,
     protobufTs: window.__GRPCWEB_DEVTOOLS_PROTOBUF_TS__?.protocolVersion,
   })
   ```

6. Test replay only with a request that is safe to send again. Select a captured
   request, choose **Edit**, update its JSON, and choose **Send request**. The
   replay should appear as a new entry linked to the original request.

## Replay safety and limits

Replay makes a real backend call. It can repeat a mutation and may reuse
captured authentication or metadata. Do not use replay as a connectivity test
against production.

- Only a request already captured by the Inspector can be replayed.
- The originating frame and its instrumented client or interceptor must still
  be alive.
- Replay handles are limited to the 100 most recently used handles per
  transport.
- The full request must remain in the panel payload cache and be 5 MiB or
  smaller.
- Reloading, navigating, or browser-discarding the page destroys its live
  client objects and replay handles.
- Client-streaming and bidirectional-streaming calls are not supported.

## Troubleshooting

### No requests appear

- Confirm that the matching API exists in the inspected page's console, not an
  extension console.
- Reload with DevTools open and issue a new RPC.
- For generated `grpc-web`, register every active client instance and keep both
  the immediate API check and readiness listener.
- For Connect-ES or protobuf-ts, confirm the late-bound wrapper is in the
  transport instance actually used by the generated service client.
- If a project has several factories or workspace packages, trace each active
  browser client separately.

### Requests appear only after a reload

Use immediate registration plus the readiness event for generated `grpc-web`,
or a per-call late-bound wrapper for Connect-ES and protobuf-ts. Do not add an
arbitrary delay.

### Capture stops after the tab is idle

Current extension builds reconnect the panel and content bridge automatically.
Wait briefly or choose **Reconnect**. Do not add application RPCs or timers only
to keep an extension worker alive. If the browser discarded the entire tab,
reload it and capture new requests.

### Replay is unavailable or rejected

- Capture a fresh request if the frame was reloaded or its handle was evicted.
- Check for payload truncation and the 5 MiB limit.
- For generated `grpc-web`, add a method-specific `createRequest` or `fromJson`
  adapter when generated setters cannot reconstruct a custom value.
- Keep the Inspector interceptor before authentication and retry interceptors
  so replay reaches the intended application pipeline.
